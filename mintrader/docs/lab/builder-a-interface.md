# Lab core - interface notes (Builder A, 12 Oct 2026)

Written by the lab core build for the builders of the nightly runner, the practice runner and the showcase. The code in mintel/lab/ is the authority; these notes summarise it.

Everything is additive except the BEHAVIOURS marked CHANGED. B and C: please read the CHANGED items.

lab/__init__.py: + clamp_fresh_cap(n) (0..30); + REASON_EXTEND_GRID, REASON_FITS_NOISE, REASON_PLATEAU_PENDING, HOLD_BACK_REASONS. CHANGED: LabSettings.fresh_cap_per_stretch above 30 reads as 30 (can be lowered, never raised).
cut.py: CHANGED: CutState.fresh_cap is clamped to 0..30 whenever a state is built or loaded; set_cut/ensure_cut clamp.

ledger.py: tests table gains two trailing columns, assumed_share REAL and gated INT DEFAULT 0 (older files are migrated on open; the spec's own columns are untouched and first). TEST_COLUMNS gains 'assumed_share' and TestStats.to_cols() gains the same key. New TEST_EXTRA_COLUMNS, TRIGGERS (SCHEMA is now tables only; both are applied by LabLedger.__init__). New trigger fresh_row_is_sealed: no column of a done fresh row can change.
 CHANGED: begin_test raises LedgerError for an id that was never register()ed. n_tests() counts tests rows directly; n_by_family() files unregistered rows under ''.
 CHANGED: regrade_past(test_id, plateau=None|ok|spike|extend|na, passed, reasons, dsr=None) now sets gated=1, accepts plateau None ('a neighbour is not tested yet'), and never turns a past row that failed its own checks into a pass (it keeps the earlier failure reasons). Tests that used it to FORCE a pass must force it in SQL (UPDATE tests SET passed=1) first.
 CHANGED (B must do this): claim_fresh / fresh_once now refuse (FreshRefused code NO_PAST_PASS, reason in the message) unless the past row has been through regrade_past, its plateau is not NULL/'extend', its reasons hold none of EXTEND_GRID / FAMILY_FITS_NOISE / PLATEAU_PENDING, and families(code, stretch).pbo is not above 0.35. So at the end of each family B must call regrade_past for EVERY past row that passed (even if nothing changed) before step 8: plateau=state from plateau_state (None while a sibling is missing), passed=v.passed, reasons=v.reasons, where v = past_verdict(TestStats.from_row(row, daily), state, pbo_ok=not family_gate(...)['blocks']). A family cut short by the deadline therefore forwards nothing until its end-of-grid step has run.
 The fresh cap passed to claim_fresh is clamped to 30.

stats.py: CHANGED: block_bootstrap_p (hence TestStats.p, luck_of_daily, practice p) is now a bootstrap-t; signature, seed, blocks and 2,000 resamples unchanged; fewer than 2 days gives 1.0; values differ from before (generally larger p for small-win/big-loss payoffs). CHANGED: past_verdict(plateau=None) returns passed True, forward_ok False, reasons ['PLATEAU_PENDING']. + missing_siblings(candidate, nets) -> the neighbour Candidates plateau_state is waiting for; when plateau_state returns None, B should test those (begin_test/finish_test work on BINNED ids; they count toward N) and recompute, otherwise the candidate is never forwarded. CHANGED: dsr_of(daily, n_trials, trial_sharpes) expects the ANNUALISED Sharpes the ledger holds (LabLedger.family_sharpes) and converts them. CHANGED: fresh_verdict with fewer than 20 days (FRESH_DAYS_MIN) is outcome/reasons TOO_FEW_TRADES (one retry later). TestStats.from_row restores assumed_share.

store.py: CHANGED: past_window's limit is always the cut registered in cut.json, whether the cut comes as cut_day= or cut=<CutState>. + BarStore.overlap(symbol, t, o, h, l, c, shift=0). index.json may carry optional ints topup_from and heal_from (cleared when healed).
fetch.py: + FetchReport.clashes {symbol: {from, to, minutes, note}}; CHANGED: a symbol with prices left out adds one line to FetchReport.errors (so .ok is False) -- a WARNING for the night (stored prices are intact, the rest of the fetch and the later steps should carry on; show it in the nightly note). is_synthetic_feed(feed, ping_info=None): a ping() dict whose 'backend' contains 'sim' means SYNTHETIC. B's PriceFeed.ping() must therefore return the bridge's ping dict (with 'backend') unchanged, or the feed must set .synthetic.
features.py: + known_days(calendar); CHANGED: covered_days counts only days with a recorded release (so window.news_days and candidate.news_ready are stricter); PdlEngine ignores non-weekday UK days (feature cache restamps itself automatically).
candidate.py: + swings(x), SWING_NOTE exported; names/words reworded (ids unchanged; VWAP_FADE title format changed).
sim.py: CHANGED: close_trade stamps TIME / SESSION_END / FEED_GAP exits at the exit bar's open + 1 minute (new AT_THE_CLOSE); practice should keep passing the OPEN minute of the completed bar. Comment on sizing corrected, behaviour unchanged.

Not changed: Candidate/Signal/Trade/Result/WindowInfo, ids and grid hash (632/664), LabPaths, fresh_once signature, the other store/ledger/cut/fetch signatures.
